# Wisp: умные обновления и оптимизация — дизайн

**Дата:** 2026-10-24
**Статус:** согласовано с владельцем проекта

## Зачем

Wisp — Android-менеджер VPN-подписок. На мобильном интернете пользователь часто
оказывается за белым списком провайдера: GitHub и сайты подписок недоступны
напрямую. На Wi-Fi доступ обычно открыт. Сейчас приложение всегда ходит через
Яндекс-переводчик и проверяет обновления на любой сети, что на мобильном
интернете бесполезно, а на Wi-Fi медленнее, чем нужно.

Цель — чтобы на Wi-Fi приложение само поддерживало подписки и проверяло
обновления, а на мобильном интернете не тратило время на заведомо неудачные
запросы и давало пользователю ручной выбор «напрямую / через Яндекс».
Заодно — поддержать все распространённые протоколы подписок и убрать несколько
узких мест по скорости и размеру.

## Цели

- Определять тип соединения: Wi-Fi / мобильный интернет / нет сети.
- На Wi-Fi: проверять достижимость интернета быстрым пробным запросом, затем
  автоматически проверять обновление приложения и обновлять все подписки.
- На мобильном интернете и без сети: никаких автоматических запросов.
- Ручное обновление подписки всегда предлагает два пути: напрямую и через
  Яндекс-переводчик.
- При потере сети ждать её появления (cooldown) и повторять попытку при
  изменении подключения, пока приложение открыто.
- Парсить `vless`, `trojan`, `vmess`, `hysteria`, `hysteria2`, `hy2`, `ss`,
  `ssr`, `tuic` — и в HTML, и в сыром тексте.
- Небольшие оптимизации: один общий `OkHttpClient`, кэш форматтера дат,
  предкомпилированные регулярные выражения, удаление неиспользуемой
  зависимости.

## Не-цели

- Kotlin Multiplatform, iOS, Windows, Compose Multiplatform.
- Публикация в App Store, Apple Developer, TestFlight, `.ipa`.
- Изменение механики установки APK-обновлений (FileProvider, неизвестные
  источники) — только условие запуска проверки.
- Собственный VPN-клиент или подключение к серверам.

## Ограничения

- Только Android, один модуль `:app`, View-система.
- `minSdk 24`, `targetSdk 35`, `compileSdk 37`, AGP 9.4.0, Gradle 9.8.0
  (Kotlin встроен).
- Новые runtime-зависимости не добавляются; для тестов — только MockWebServer
  той же версии, что и OkHttp (4.12.0).
- Release-сборка сохраняет `minifyEnabled` и `shrinkResources`.
- Автоматические проверки работают только в foreground (`onStart`–`onStop`).
- Тексты интерфейса — на русском.
- Серверы и URL не хардкодятся в UI-коде, кроме пробного адреса и GitHub-
  репозитория, которые уже заданы в проекте.

## Рассмотренные подходы

### A. Android-only + сетевой слой на OkHttp (выбран)

Остаёмся в одном модуле. Новый пакет `com.wisp.network`: общий `OkHttpClient`,
`NetworkMonitor` (тип сети), `InternetChecker` (пробный запрос),
`SubscriptionFetcher` (загрузка подписки). Автообновление на Wi-Fi идёт через
OkHttp в фоне, без WebView. Ручное обновление по-прежнему открывает WebView —
так сохраняется проверенный обход через Яндекс и возможность сохранить страницу.

Плюсы: минимум изменений, нет новых runtime-зависимостей, автообновление не
зависит от UI. Минусы: два пути загрузки (OkHttp и WebView) нужно держать
согласованными по парсингу.

### B. KMP + Compose Multiplatform (отклонён)

Имел смысл для iOS и Windows. После отказа от iPhone и desktop добавляет
модуль, `expect/actual` и сложность сборки без выгоды. Отклонён владельцем.

### C. Всегда напрямую или всегда через прокси (отклонён)

«Всегда напрямую» ломается на мобильных белых списках. «Всегда через прокси»
медленнее на Wi-Fi и раскрывает трафик Яндексу без необходимости. Нужен выбор
по типу сети.

### D. Автообновление через WebView (отклонён)

Требует видимого экрана, медленно, мешает пользователю. Для фонового
обновления достаточно OkHttp: подписки — это текстовые/HTML-страницы.

## Принятые решения

- **Пробный адрес:** `https://cp.cloudflare.com/generate_204`, HEAD-запрос,
  таймауты 3 с. Ответ 204 — интернет есть. Google-адрес отклонён: в РФ может
  throttling-иться. `example.com` отклонён: тяжелее и отдаёт HTML.
- **Автообновление подписок:** не чаще одного раза в 15 минут, отметка в
  `wisp_prefs` (`last_auto_refresh`). Проверка обновления приложения сохраняет
  собственный 24-часовой троттлинг.
- **Ручное обновление:** диалог выбора из двух пунктов, а не две постоянные
  кнопки — не раздувает строку конфига. На Wi-Fi доступны оба пункта, на
  мобильном — оба, на «нет сети» — только сообщение.
- **Загрузка подписок в auto-режиме:** последовательная, чтобы не нагружать
  сеть и память; тело ограничено 5 МБ; текущий открытый в WebView конфиг не
  перезаписывается.
- **Извлечение текста из WebView:** вместо `outerHTML` собираем текст из
  `pre`, `code`, `textarea`, а если таких элементов нет — берём
  `document.body.innerText`; меньше памяти и работает с подписками в
  `<textarea>`.
- **Парсер:** единый список протоколов, построчный поиск, дедупликация через
  `LinkedHashSet`; для HTML сначала берём блоки `<pre>`, для сырого текста —
  все строки.
- **VPN:** при активном VPN тип сети определяется по нижележащим сетям; для
  автообновления нужен именно Wi-Fi. Ручной прямой запрос доступен всегда,
  кроме полного отсутствия сети.
- **Версия:** 4.1 (versionCode 5). Автообновление читает GitHub Releases, а не
  git-теги; тег нужен только чтобы создать релиз.
